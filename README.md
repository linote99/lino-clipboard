# Lino-clipboard —— 剪贴板同步（设备端）插件

把安卓设备（UFI 本机，如 U30 Air）的**系统剪贴板**与 UFI-TOOLS 高级后台打通：

- 设备上任何应用复制的内容，都能在插件折叠栏里查看，并留下历史记录
- 折叠栏输入框里写的内容，可一键写入设备剪贴板，之后在 ufi 设备上直接粘贴
- 历史条目可「复制」到当前浏览器的剪贴板
- 历史可单条「删除」，也可「清空」全部（需连点 3 次确认）
- **开机自启**：开启后重启设备自动恢复监听，无需手动操作
- **卸载**：一键彻底清除（停监听 + 移除自启 + 删工具与历史）

## 交付文件

| 文件 | 说明 |
|---|---|
| `lino-clipboard.js` | **插件本体**，直接贴进高级后台「插件功能」即可（约 57 KB，含内嵌设备端工具与自启脚本） |
| `src/lino/clipctl/Cli.java` | 设备端工具源码（剪贴板读写与监听） |
| `build_plugin.py` | 构建脚本：把编译好的 dex 以 base64 内嵌进插件模板 |
| `plugin_template.js` | 插件模板（`__CLIPCTL_DEX_B64__` 占位） |
| `build/dex/classes.dex` | 编译产物（约 14.5 KB） |
| `boot_start.sh` | 开机自启脚本源文件 |
| `verify/` | 端到端验证用的 harness 与探针（含自启/卸载用例） |

## 为什么必须有设备端工具

这不是多余的一层。Android 10+ 的 `ClipboardService.clipboardAccessAllowed()` 在「读」剪贴板时要求调用方满足三者之一：

1. 持有签名级权限 `READ_CLIPBOARD_IN_BACKGROUND`
2. 是当前默认输入法
3. 当前拥有窗口焦点

UFI-TOOLS 的网页所在应用退到后台时，三条**全部不满足** —— Web 层拿到的永远是空，也收不到剪贴板变化事件。纯前端方案（`navigator.clipboard`）在这台设备上做不到这件事。

本机的可用突破口：`com.android.shell`（uid 2000）**持有** `READ_CLIPBOARD_IN_BACKGROUND`。所以设备端工具以 uid 2000 身份调用 `IClipboard`、并把 `callingPackage` 传成 `com.android.shell`，就能无焦点读写，且内容由 `system_server` 持有，进程退出也不丢。

两个实测踩到的坑（都已规避，写在源码注释里）：

- **不能用 `ClipboardManager`**：`opPackageName` 与 uid 不匹配时它会**静默失败** —— `setPrimaryClip` 不抛异常但不生效、`getPrimaryClip` 直接返回 `null`。所以工具直连 `IClipboard` AIDL。
- **root 身份反而不行**：`AppOpsManager.checkPackage(0, "com.android.shell")` 会因包与 uid 不匹配抛 `SecurityException`。所以工具若被 root 调起，会先 `android.system.Os.setuid(2000)` 降权（用 `Os` 而非反射 `Process.setuid`，后者在 Android 11+ 属 non-SDK 接口，实测 `NoSuchMethodException`）。

## 安装与使用

1. 高级后台 →「插件功能」→ 贴上 `lino-clipboard.js` 内容 → 保存
2. 主页「功能列表」出现 **剪贴板同步** 按钮
3. 主页会出现 **剪贴板同步** 折叠栏（结构参照 CloudFlare 插件：挂到 `.functions-container` 之后，
   标题行 `strong` + 状态 + 折叠开关，内容为 `.collapse > .collapse_box > ul.deviceList > li` 卡片）：
   - **写入设备剪贴板**：把输入框内容写进设备剪贴板（带回读校验，写不进去会明确报错）
   - **读取当前剪贴板**：把设备当前剪贴板内容拉进输入框
   - **刷新历史 / 清空历史**：都在「📋 剪贴板历史」分区内
   - **开启后台监听**：启动常驻进程持续记录新的复制内容
   - 历史条目每行有两个按钮：**写入**（写到 ufi 设备剪贴板）、**复制**（复制到当前浏览器的剪贴板）
   - **开启开机自启**：在「🧩 设备端工具与插件设置」区，把自启行写进 `/sdcard/ufi_tools_boot.sh`，重启后自动恢复监听
     （开启后按钮变「关闭开机自启」并高亮）
   - **安装设备端工具**：必须先手动安装，见下方「设备端工具与插件设置」
   - **卸载**：停监听 + 移除自启 + 删工具与历史，目录整个清除（需连点 3 次确认）
   - **使用说明**：面板内不再内嵌任何功能说明文字，全部集中到这个按钮打开的弹窗里

前提：**必须开启高级功能（root）**。未开启时折叠栏仍能展开，但会明确显示「未开启高级功能」，不会崩溃。

### 开机自启怎么实现的

UFI-TOOLS 平台自带的 `/sdcard/ufi_tools_boot.sh` 在开机窗口内由 samba 的
`root preexec` 以 **root**（`u:r:su:s0`）执行。插件往它末尾追加一行带标记的调用：

```
sh /data/local/tmp/lino_clipboard/boot_start.sh #lino_clipboard_autostart
```

`boot_start.sh` 会先等 `sys.boot_completed=1`（开机早期 clipboard 服务常未就绪），
再用 `setsid` 拉起监听，并检查 pidfile 避免重复启动。

摘除时用 `grep -vF` 重写整个文件，且**只在 grep 正常返回时才覆盖** ——
否则读失败会把用户其它的自启项一起清空。移除后脚本与原文件逐字节一致（已实测）。

### 卸载的安全性

- 卸载按钮需**连点 3 次**（6 秒内有效）才执行，避免误触
- 只删写死的 `/data/local/tmp/lino_clipboard`，不碰其它插件目录
- 卸载顺序是「停监听 → 移除自启 → 删文件」，避免留下还在写历史的孤儿进程

## 设备端工具与插件设置

### 怎么安装

**必须手动安装。** 展开折叠栏 →「设备端工具」分区 → 点「安装设备端工具」。

插件**不会**自动安装：未安装时所有剪贴板操作（写入/读取/开监听/开自启）都会失败，
并提示「请点击安装「安装设备端工具」」。这是刻意的设计——安装是一次显式的设备写入，
放在用户明确点击之后，才能保证显示状态与实际一致。

安装状态由按钮文字体现（面板上没有独立的状态徽标）：

| 状态 | 按钮文字 | 说明 |
|---|---|---|
| 未安装 | 安装设备端工具 | 设备上还没有这个文件 |
| 已安装 | 已安装 | 高亮显示；再点一次即覆盖重装 |
| 需要高级功能 | （禁用） | 未开高级功能，写不了设备文件 |

安装前若监听正在运行，会先停掉、装完再自动恢复 —— 因为运行中的进程持有旧 dex，
不重启进程就会出现「显示已安装但行为还是旧的」。

设备端工具是一个 `app_process` 跑的 dex，不是 APK，
不装应用、不要 Magisk 模块、不注册任何系统组件：

1. 插件本体里以 base64 内嵌着这份 dex（约 14.5 KB）
2. 点安装按钮时执行（**不会**因为读写操作而自动触发）：
   ```
   mkdir -p /data/local/tmp/lino_clipboard
   printf '%s' '<内嵌 base64>' | base64 -d > clipctl.dex.tmp
   mv clipctl.dex.tmp clipctl.dex && chmod 644 clipctl.dex
   ```
3. 写完校验「文件存在且大小非 0」，用于发现写失败（空间不足、base64 截断等）；
   校验不过会明确报错，不会装作成功

**每次点安装都是覆盖写入**，不做版本比对 —— 设备上原本那份是什么版本不影响结果。

### 怎么卸载

「卸载」按钮需**连点 3 次**（6 秒内）确认：

| 按钮 | 效果 |
|---|---|
| 卸载 | 停监听 → 移除开机自启 → 删整个设备端目录（工具 + 历史） |

「安装设备端工具」「开启开机自启」「卸载」三个按钮在同一行。

面板上**没有独立的状态徽标**，安装状态直接由安装按钮的文字体现：

| 状态 | 按钮文字 |
|---|---|
| 未安装 / 未开高级功能 | 安装设备端工具 |
| 已安装 | 已安装（高亮，可再点覆盖重装） |

**手动卸载**（不想用按钮时）：

```sh
# 1) 停掉监听
kill -9 "$(cat /data/local/tmp/lino_clipboard/clip.pid)" 2>/dev/null
# 2) 从开机脚本摘掉自启行（保留其余内容）
grep -vF 'lino_clipboard_autostart' /sdcard/ufi_tools_boot.sh > /tmp/b && mv /tmp/b /sdcard/ufi_tools_boot.sh
# 3) 删目录
rm -rf /data/local/tmp/lino_clipboard
```

> 第 2 步别用 `rm` 整个删掉 `/sdcard/ufi_tools_boot.sh` —— 那里面还有你自己其它插件的自启项。

### 卸载是否干净

- 只动 `/data/local/tmp/lino_clipboard` 这一个目录（名字写死，不会误伤别的插件）
- 开机脚本用 `grep -vF` 摘行重写，只在 grep 正常返回时才覆盖，避免读失败把别人的自启项清空
- 卸载后启动脚本与操作前**逐字节一致**（已实测比对）
- 不残留进程：先停监听再删文件，不会留下还在写历史的孤儿进程

## 数据落盘

| 路径 | 用途 |
|---|---|
| `/data/local/tmp/lino_clipboard/clipctl.dex` | 设备端工具（自动部署，约 14.5 KB） |
| `/data/local/tmp/lino_clipboard/boot_start.sh` | 开机自启落地脚本（仅开启自启时存在） |
| `/data/local/tmp/lino_clipboard/history.jsonl` | 历史，每行 `{"t":时间戳,"s":文本}` |
| `/data/local/tmp/lino_clipboard/clip.pid` | 监听进程 pid |
| `/data/local/tmp/lino_clipboard/watch.log` | 监听进程日志 |

历史以**设备文件为唯一数据源**，`localStorage` 只作首屏缓存 —— 换浏览器打开高级后台，读到的是同一份历史。文件超 512 KB 自动裁剪，只留尾部 400 行。

## 已实测通过的场景

在 U30 Air（Android 13，UFI-TOOLS 4.1.5）上，用真实宿主页面（插件经平台自身的 `/api/get_custom_head` 通道注入）端到端验证：
- 环境自检 → 「设备剪贴板可读写」
- 写入含中文与 emoji 的文本 → 出现在历史 → 回读往返一致
- 开启后台监听 → 状态变「后台监听中」→ 设备端进程存活
- **另一个进程写入剪贴板（等价于用户在别的 App 里复制）→ 被监听捕获并记入历史**
- 9000 字中文长文本写入 + 回读 + 记录均正常
- 历史去重（同内容只留最近一次）、按时间倒序、制表符/换行/引号/反斜杠/emoji/URL 原样保留
- 反复展开/初始化不产生重复折叠栏 / 重复按钮 / 重复 style（`ensurePanel` 幂等 + 事件只绑一次）
- **与插件收纳箱的「插件改写」兼容**：按其 v1.2 的识别规则逐条复核，本折叠栏
  不被判为内置面板、不在 `.mask` 内、有内容、标题可推导为「剪贴板同步」——
  `skipReason` 为空，即**可被改写**；同页面只此一个可改写面板，不产生噪音条目
- 历史按钮为 **写入 / 复制** 两个（原「填入」已改成「复制」）；
  复制调用 `navigator.clipboard.writeText`，内容与原文完全一致
- **安装按钮**：从「未安装」状态点按钮 → 变为「已安装」→ 随后写入剪贴板正常；重复点击幂等
- **不自动安装**（重点）：未安装时写入 / 读取 / 开监听 / 开自启**全部被拦截**，
  并提示「请点击安装「安装设备端工具」」；整轮操作后设备端仍无文件，确认没有偷偷安装
- 手动安装后立即恢复可用：写入成功、历史记录正常
- **无版本校验**：把设备上的 dex 换成任意内容，插件仍判定「已安装」、功能正常
  （不会再出现「版本不符 / 更新设备端工具」）
- **布局**：开机自启按钮与写入/读取/监听同处一行按钮区，不再单列分区
- **手动卸载**后设备状态干净：目录消失、监听进程为 0、启动脚本还原
- 空内容写入被拒绝且不崩
- 未开高级功能时正确降级为「未开启高级功能」
- **开机自启**：经插件 UI 开启 → 真实重启设备 → 监听进程被自动拉起 → 重启后读写与历史记录均正常
- **卸载**：目录整个消失、历史清空、自启关闭、UI 复位；启动脚本还原为原始内容（逐字节比对一致）
- 安装状态由安装按钮文字体现（无独立状态徽标）
- **面板无内嵌说明文字**：「本插件不装 APK」「历史保存在」「彻底卸载：…」等提示均已从面板移除
- **使用说明按钮**与安装/自启/卸载同行；点开的弹窗包含写入、历史、设置、后台监听四节说明，
  且不重复叠加（多次点击仍只有一个弹窗）
- 开机自启按钮位于「设备端工具与插件设置」区内，写入区内不再有该按钮
- 卸载需连点 3 次；只点 1~2 次不会执行

复跑方式见 `verify/`：`node harness_server.js` 起宿主（`/api/root_shell` 用 adb 真执行到设备），
再用 chromium headless 加载并 dump 探针输出。

## 已知限制

- 不做自动轮询：每次设备操作都是一次 HTTP 往返，改成「展开时拉一次 + 手动刷新 + 写入后回读」，避免后台持续占用
- 「复制」依赖浏览器的剪贴板权限；http 非安全上下文下 `navigator.clipboard` 不可用，
  已用临时 `textarea` + `execCommand('copy')` 兜底，仍失败则提示手动选中复制
- 只能同步**文本**，图片/文件不处理
- 依赖 `/data/local/tmp` 可写；若被系统（或重启）清理，点一次「安装设备端工具」即可恢复
  （自启脚本在下次启动时因找不到 dex 会静默跳过，不会报错刷屏）
- 开机自启依赖平台的 `/sdcard/ufi_tools_boot.sh` 机制；若该文件被平台重建，需重新开启一次
